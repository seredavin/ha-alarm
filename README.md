# Wake-up Alarm — будильник с рассветом для Home Assistant

Кастомная интеграция: будильник на каждую комнату, который будит «рассветом».

- Диммируемый свет плавно разгорается за N минут до подъёма и к времени подъёма горит на 100%.
- Недиммируемый свет и розетки включаются ровно в момент подъёма.
- Яндекс Станция (или любая колонка) включается за M минут, громкость плавно растёт до максимальной.
- Шторы открываются перед подъёмом, если солнце уже над горизонтом.
- Если кто-то включил, выключил или подкрутил свет либо остановил Станцию, будильник считает, что человек проснулся, и останавливается.

Всё настраивается в UI. Параметры можно менять в любой момент, даже во время рассвета.

## Установка

1. HACS → ⋮ → **Custom repositories** → `https://github.com/seredavin/ha-alarm`, тип **Integration**.
2. Найти **Wake-up Alarm**, установить, перезапустить Home Assistant.
3. **Настройки → Устройства и службы → Добавить интеграцию → Wake-up Alarm.**

Минимальная версия Home Assistant — 2025.1.

## Создание будильника

Один будильник — одна запись интеграции (например, «Спальня», «Спальня Александра»). При создании выбираются:

| Поле | Что это |
|---|---|
| Название | Имя будильника и устройства |
| Источники света | Любые `light` и `switch` (лампы, розетки). Интеграция сама определяет, что диммируется |
| Колонка | `media_player`, например Яндекс Станция |
| Шторы | `cover` |

В **Настройках** записи (options) дополнительно задаются:

| Параметр | По умолчанию | |
|---|---|---|
| Тип медиаконтента | `command` | Для Яндекс Станции: `command` (голосовая команда) или `text` (произнести) |
| Медиаконтент | `включи мою волну` | Команда или контент для `media_player.play_media` |
| Стартовая громкость | 5% | С неё начинается нарастание |
| Позиция штор | 100% | Для штор без позиционирования вызывается `open_cover` |
| Минимальная высота солнца | 0° | Шторы открываются, только если `sun.sun` → `elevation` не ниже |
| Останавливать при изменении освещения | вкл | См. ниже |

## Сущности будильника

| Сущность | Назначение |
|---|---|
| `switch` Включён | Главный выключатель |
| `time` Время подъёма | Момент, когда свет на 100% |
| `switch` Понедельник … Воскресенье | Дни срабатывания. Если не выбран ни один день, будильник разовый и сам выключится после срабатывания |
| `switch` Пропустить следующий | Пропустить ближайшее срабатывание целиком |
| `number` Длительность рассвета | 1–60 мин, по умолчанию 15 |
| `number` Включать Станцию за | 0–60 мин, по умолчанию 2 |
| `number` Максимальная громкость | 0–100%, по умолчанию 50 |
| `number` Открывать шторы за | 0–60 мин, по умолчанию 15 |
| `number` Отложить на | 1–30 мин, по умолчанию 9 |
| `number` Автостоп через | 0–120 мин, по умолчанию 30 (0 — не останавливать) |
| `button` Стоп / Отложить / Тест | Управление |
| `sensor` Следующее срабатывание | Дата и время |
| `sensor` Состояние | `off`, `scheduled`, `sunrise`, `ringing`, `snoozed` |

## Как ведёт себя будильник

- **Рассвет.** Яркость растёт по перцептивной кривой (гамма 2.2): первые минуты свет едва тлеет. Если лампа уже горит ярче кривой, будильник её не приглушает.
- **Стоп.** Останавливает Станцию и возвращает громкость, которая была до будильника. Свет и шторы не трогает.
- **Отложить.** Ставит Станцию на паузу на «Отложить на» минут, затем она снова играет на максимальной громкости. Свет остаётся включённым.
- **Остановка при изменении освещения.** Будильник останавливается, если не он сам выключил источник, включил источник раньше времени, изменил яркость больше чем на 5% или остановил Станцию. Ответные сообщения устройств (MQTT-эхо, округление яркости) и недоступность устройства не считаются.
- **Перезапуск HA во время рассвета.** Рассвет продолжается с текущего места. Если время подъёма уже прошло, повторно не запускается.

> Если источником управляет ваша автоматизация (например, «торшер включается вместе со светом»), будильник увидит включение торшера и решит, что человек проснулся. Либо не добавляйте такой источник в будильник, либо отключите «Останавливать при изменении освещения».

## Сервисы и события

```yaml
action: wakeup_alarm.trigger      # тестовый прогон
target:
  device_id: <устройство будильника>
data:
  duration: 60                    # сжать весь сценарий в 60 секунд
```

`wakeup_alarm.stop` и `wakeup_alarm.snooze` принимают такой же `target`.

События: `wakeup_alarm_sunrise_started`, `wakeup_alarm_ringing`, `wakeup_alarm_snoozed`, `wakeup_alarm_stopped`. В данных события есть `entry_id` и `name`, у `stopped` ещё `reason`: `button`, `service`, `auto`, `manual`, `disabled`.

```yaml
triggers:
  - trigger: event
    event_type: wakeup_alarm_ringing
    event_data:
      name: Спальня
actions:
  - action: switch.turn_on
    target:
      entity_id: switch.kofevarka
```

## Пример карточки

```yaml
type: entities
title: Будильник — Спальня
entities:
  - switch.spalnia_vkliuchen
  - time.spalnia_vremia_podiema
  - sensor.spalnia_sleduiushchee_srabatyvanie
  - sensor.spalnia_sostoianie
  - number.spalnia_dlitelnost_rassveta
  - number.spalnia_vkliuchat_stantsiiu_za
  - number.spalnia_maksimalnaia_gromkost
  - number.spalnia_otkryvat_shtory_za
  - type: buttons
    entities:
      - button.spalnia_stop
      - button.spalnia_otlozhit
      - button.spalnia_test
```

Точные `entity_id` смотрите на странице устройства будильника. Они зависят от языка системы на момент создания.

## Требования к Яндекс Станции

Нужна интеграция [YandexStation](https://github.com/AlexxIT/YandexStation). Команды типа `command` надёжнее всего работают, когда Станция доступна по локальной сети.
